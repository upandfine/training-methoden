## Stufe 2 — Vertikale Tiefe für 25 Kernmethoden

Ziel: Aus dem 150er-Katalog (Stufe 1) werden 25 Methoden zu echten
Handbuch-Einträgen ausgebaut: Schritt-für-Schritt-Ablauf, Varianten,
Stolperfallen, Quellen.

### Schema (Stufe-2-Felder, alle optional, top-level)

```yaml
stage_2_status: ai_draft | human_reviewed
stage_2_author: "..."

steps:                       # geordnete Schritt-für-Schritt-Anleitung
  - order: 1
    label: "Setup & Framing"
    duration_minutes: 10
    trainer_action: >
      Was die Leitung konkret tut.
    participant_action: >
      Was die TN tun.
    note: >                  # optional, Tipp/Warnung
      ...

variations:                  # 3-5 Varianten pro Methode
  - name: "Remote-Variante"
    description: >
      ...
    when_to_use: >
      ...
    setting_codes: [remote_sync]   # optional

pitfalls:                    # typische Fehler + Gegenmaßnahme
  - issue: >
      Was schiefgeht.
    countermeasure: >
      Wie die Leitung reagiert.
    severity: common | rare
    setting_codes: [...]     # optional

sources:                     # schon vorhandenes Format, um mehr Einträge erweitert
  - kind: book | article | url | standard | tool
    title: "..."
    author: "..."
    year: 2005
    url: "..."
    doi: "..."
    relation: originator | reference | practice_guide
    note: "..."
```

## Nach Stufe 2 — Nächste Schritte

### Kurzfristig (Wochen)

- **Review-Pass Stufe 2:** die 25 `stage_2_status: ai_draft` auf
  `human_reviewed` heben. Methoden-für-Methode, Fokus auf Ablauf und
  Stolperfallen.
- **Stufe-2-Batch 2 (ca. 25 weitere):** Kandidaten aus Batch 1b/1c —
  u.a. `brainstorming`, `mindmap`, `kugellager`, `elevator-pitch`,
  `dot-voting`, `gallery-walk`, `kopfstand-technik`, `walt-disney-methode`,
  `reflecting-team`, `ls-25-10-crowd-sourcing`.
- **API-Tests:** FastAPI-TestClient gegen in-memory-SQLite wo möglich,
  sonst pytest-postgresql. Listen-, Detail- und Search-Endpoints.

### Mittelfristig (Monate)

- **Embeddings + semantische Suche:** Embedding-Spalte befüllen
  (OpenAI `text-embedding-3-small`, 1536 dim), HNSW-Index anlegen,
  `/search` um Vektor-Fallback erweitern.
- **UI-Prototyp:** Next.js / SvelteKit-Frontend gegen die API.
  Filter-Dropdowns, Methoden-Detailseiten, Suche.
- **Authentifizierung:** API hinter Auth (Clerk / Auth0 / own), Rollen
  `trainer` / `editor` / `admin`, `review_log` an die API anbinden.

### Längerfristig

- **Inhaltliche Lücken schließen:** Sprachlern-Methoden,
  Theater-/Dramapädagogik, politische Bildung (Betzavta etc.),
  Gewaltfreie Kommunikation.
- **Personalisierung:** TN-Profile, Favoriten, "Meine Methoden für
  diese Phase"-Listen.
- **Kollaborative Review-UI:** kein SQL-Editieren mehr — Methoden werden
  im Frontend editiert, Versionierung per `review_log`.

## Ehrliche Hinweise

- **Die Liste ist ein Plan, kein Kontrakt.** Beim Schreiben stellt sich manchmal
  heraus, dass zwei geplante Methoden praktisch identisch sind oder eine bessere
  Variante existiert. Dann tausche ich aus und dokumentiere es im nächsten Turn.
- **Originator-Zuschreibungen** sind in Stufe 1 nur dort gesetzt, wo ich hinreichend
  sicher bin. Im Zweifel `null`. Review durch dich (oder eine Fachperson) sollte
  diese Felder prüfen.
- **Remote-Eignung** ist bei vielen Methoden eine Einschätzung auf Basis eigener
  Praxis / Fachliteratur, kein Messwert. Bei produktivem Einsatz: Auffälligkeiten
  im `review_log` vermerken.
- **Lücken, die mir bewusst sind:** Sprachlern-spezifische Methoden, Methoden aus
  Theater-/Dramapädagogik, Methoden der politischen Bildung (Betzavta etc.),
  Methoden der Gewaltfreien Kommunikation. Die würden als Batch 2 oder als
  Themen-Pakete nachkommen.
